FreedomIQ — Sprint Start Checklist
Purpose: Start every sprint with one clear, measurable product objective.
1. Sprint Workflow
1. Review latest architecture
2. Identify highest-value product gap
3. Define ONE sprint objective
4. Inspect existing implementation
5. Design minimal change
6. AI implements complete code
7. Test it
8. Review impact on existing functionality
9. Git commit
10. Sprint closure
2. Engineering Rules
•	One function = One responsibility.
•	Analysis functions return data; presentation functions display data.
•	calculate_ = calculation; print_ = presentation; plot_ = visualization; export_ = output.
•	Reuse existing functions whenever possible (DRY).
•	Keep functions short, readable, modular, and maintainable.
•	Design before coding.
•	Preserve working architecture; avoid unnecessary refactoring.
•	AI provides complete working implementations; no large manual coding expected.
•	Measure before optimizing; do not optimize from assumptions.
3. Sprint Rules
•	One objective only; no unrelated features.
•	Do not change investment logic unless it is the sprint objective.
•	Reuse existing models, services, and engines before creating duplicates.
•	Prefer the smallest justified architectural change.
4. Definition of Done
•	Code complete and integrated
•	Feature works
•	Existing functionality preserved
•	Testing completed / known issues recorded
•	Git commit completed
5. Sprint Closure
•	Objective — What was built
•	Capability Added — What FreedomIQ can do now that it could not do before
•	Files Created / Modified
•	Testing Status
•	Git Commit
•	Next Sprint
Guiding Question
What new capability does FreedomIQ have today that it didn't have yesterday?
